# تطبیق با هدف V2 — بستهٔ ۰۷

مبنای ادامه دقیقاً زیپ مرحلهٔ چهارم ضمیمه‌شده بود؛ تمام hashهای فایل‌ها و برابری آن با کد محلی بررسی شد. نسخهٔ کامل و دست‌نخوردهٔ برنامهٔ هدف در planning/Target_Plan_V2.zip نگه داشته شده است.

**شمارهٔ بسته با شمارهٔ فاز یکی نیست. بستهٔ هفتم به معنی تکمیل فاز پنجم یا آماده‌شدن رلیز نیست.**

| فاز هدف | ساخته و آزموده | باقی‌مانده/معیار خروج |
|---|---|---|
| ۱: core و قرارداد | codec انواع، parser سخت‌گیر، مالکیت داده، محدودیت پیام، تست میزبان و sanitizer | memory map برد و build firmware؛ گزارش کامل PASS فاز هنوز صادر نشده |
| ۲: شبکه، ساعت و صف | صف فرمان، outbox پاسخ، monitor ساعت و stamp اکتساب، کنترل انقضا، counters و inbox محدودِ قطعه‌های شبکه | adapter واقعی ساعت، MQTT/TLS/ACL، reconnect، adapter شبکهٔ واقعی، backoff، broker دو node و نمودار/آزمون قطع اتصال |
| ۳: حسگرها و FDC | قرارداد generic نوع‌دار در core | callback/درایور واقعی، شش درایور هدف، FDC و آزمون خرابی سخت‌افزار |
| ۴: فرمان و موتور | sample مصنوعی تا پاسخ میزبان، مجوز واقعی رجیستری، dedup و حالت‌های نتیجه | sample سخت‌افزاری، scheduler/set_rate واقعی، trace نسل و replay مشترک موتور/پنل |
| ۵: پردازش و انتشار | شواهد قابل بازتولید نرم‌افزار | baseline/shadow/active، سازگاری عددی Pipeline، آزمایش پژوهشی، soak، نصب/کامپایل تمیز و رلیز |

## تفاوت‌هایی که نباید پنهان بمانند

- پروفایل فعلی ۸ کانال و ۸ فرمان صف دارد؛ history فعلاً ۱۶ entry است، در هدف ۳۲ entry پیشنهاد شده. افزایش ظرفیت یا تأیید همین ظرفیت باید با بودجهٔ حافظه و تست ثبت شود. full32 کانال ساخته نشده.
- history جلوگیری از تکرار تا پایان TTL اصلی حفظ می‌شود؛ retry window اضافی و نگهداری طولانی پاسخ پس از اعلام ارسال هنوز کامل نیست.
- رد پذیرش فرمان (مانند QueueFull یا Denied) فعلاً خطای محلی می‌دهد؛ هدف ok:false روی wire می‌خواهد. طراحی بافر پاسخ برای این مسیر و جلوگیری از سوءاستفاده/overflow هنوز لازم است.
- outbox تک‌پیامی پاسخ با صف کامل ارسال حسگر/شبکه یکی نیست. خواندن مستقیم Device.reading ممکن است gate زمان را دور بزند؛ مسیر محصول باید از TimedTelemetry استفاده کند.
- MonitoredClock اعتبار ورودی adapter را بررسی می‌کند؛ NTP، اندازه‌گیری واقعی عدم‌قطعیت یا adapter آمادهٔ ESP32 نیست.
- مشاهدهٔ ساعت و تست حسگرها ساختگی و برچسب‌دارند. دقت علمی، کشف جدید، صحت فیزیکی یا آماده‌بودن تمام بردها ادعا نشده است.

## اولویت ادامه

اول adapter معتبر ساعت و مسیر MQTT/TLS با publish مرتب و تشخیص واقعی retained/topic؛ سپس پوشش رد admission و retry-window مطابق هدف. بعد از اتصال واقعی دو node، درایورها و حلقهٔ موتور تکمیل شوند. نوآوری ترکیبی هدف باید در مسیر پژوهش با کنترل و ablation ارزیابی شود؛ این مرحله زیرساخت دادهٔ قابل اتکا را می‌سازد.

در بستهٔ ۰۷ inbox مستقل شبکه ساخته شد؛ این با MQTT client و TLS واقعی یکی نیست. ۳ پیام کامل و یک assembly ظرفیت دارد و برای callbackهای task جدا به lock یا handoff بیرونی نیاز است.


## پیشرفت بستهٔ ۰۷

آزمایشگاه دسکتاپ با بروکر واقعی TLS و دو گره C++ اضافه شد؛ ۱۱ سناریو پاس است. بنابراین بخش آزمون اولیهٔ broker دو گره و ACL/TLS دیگر صرفاً برنامه نیست. ردیف فاز ۲ همچنان ناقص است: adapter برد، ساعت واقعی، reconnect/backoff محصول، قطع ناگهانی حین ارسال، آزمون طولانی و تأیید مستقل CP07 باقی است. راه‌اندازی مجدد فعلی کنترل‌شده است. جزئیات در BROKER_LAB.md.


## اصلاح دامنه در بستهٔ ۰۸

هدف تمام خانواده‌های برد پشتیبانی‌شده در Arduino است؛ ESP32 فقط یکی از backendهاست. اشاره‌های پیشین به adapter ESP32 نمونهٔ یک پیاده‌سازی‌اند، نه محدودیت محصول. پروفایل فعلی برای AVR کوچک مناسب نیست؛ پروفایل کم‌حافظه، کامپایل هر core، بودجهٔ حافظه و adapter زمان/شبکه باید جداگانه تکمیل شوند. فایل ARDUINO_PORTABILITY.md معیار ادامه است. فعلاً تست روی هیچ بردی انجام نشده.


## وضعیت پس از بستهٔ ۰۹ و مسیر فاز بعد

سیاست اتصال مجدد عمومی و پیوند آزمودهٔ آن با inbox اضافه شد و بررسی مستقل ۲۹۰ مورد پاس شد. این بخش از فاز ۲ بسته شد؛ اتصال واقعی policy به backend شبکه هنوز باز است. پیش از اعلام PASS فاز ۲، باید backend با clock-before-TLS، اعتبار CA/hostname، cancel امن و قطع ناگهانی آزموده شود. گام بعدی پس از این اتصال، scheduler و شش درایور فاز ۳ است؛ قرارداد generic فعلی جای درایور فیزیکی را نمی‌گیرد. موارد memory map/پروفایل فاز ۱ نیز همچنان باز هستند. این گزارش برای گذر صوری به فاز بعد امضا نشده است.


## بستهٔ ۱۰

policy اکنون به شبکهٔ واقعی در آزمایشگاه دسکتاپ وصل و قطع ناگهانی بروکر/دو تلاش ناموفق/بازگشت و فرمان جدید آزموده شد. بنابراین این مورد دیگر فقط تست مصنوعی نیست. backend قابل نصب روی برد Arduino، cancellation غیرمسدودکننده، قطع حین پیام درحال ارسال و آزمون حافظه/برد همچنان بازند. فاز ۲ هنوز PARTIAL است؛ فاز ۳ را پایان‌یافته یا فعال سخت‌افزاری معرفی نکنید.


## بستهٔ ۱۱: اولین آداپتر API واقعی Arduino

ArduinoMqttAdapter به API واقعی و pinned ArduinoMqttClient متصل است و callback/صف و ارسال پاسخ QoS1 را اجرا می‌کند. خطای فرمان هم‌زمان با PUBACK با بررسی مستقل پیدا و در طراحی اصلاح شد. این backend همگام است؛ درایور اتصال امن و ساعت برد، حلقهٔ reconnect کامل و سفارش hello/پاسخ معلق هنوز پیاده‌سازی محصول کامل ندارند. تست native با منبع واقعی SDK انجام می‌شود ولی هیچ بردی کامپایل/bench نشده. فاز ۲ هنوز PARTIAL است.


## بستهٔ ۱۲

هماهنگ‌کنندهٔ hello/پاسخ و درز اتصال غیرمسدودکننده در تست native اضافه شد. آداپتر MQTT آردوینو هنوز همگام است و آن درز را ندارد. شش درایور فقط mock هستند؛ جدول DRIVER_STATUS فقط ستون mock را PASS می‌داند. میز، فلش ESP32، soak و RQ علمی NOT_RUN است. فاز ۲ PARTIAL، فاز ۳ mock-only، فاز ۴ و ۵ BLOCKED می‌مانند. جزئیات در PHASE_GATES.md.
